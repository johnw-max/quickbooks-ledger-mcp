# Security policy

Do not report QuickBooks writes as successful without provider ID, write receipt, and exact read-back. Do not retry `WRITE_RESULT_UNKNOWN` automatically.

Never accept workspace, Agent, installation, connection, Company/Realm, provider object ID, or standing-delegation authority from model-authored tool arguments. They must come from verified OAuth tokens, server-side connection records, target sessions, or compiler resolution.

Public Client Intake Agents must not receive this ledger MCP or its credentials. Route collected documents through a source-material store; an internal accountant Agent may then prepare a governed Accounting Case.

Keep writes disabled by default. Enabling writes also requires an explicit target policy and exact released standing-delegation actions. Rotate any credential exposed in screenshots, chat, logs, or commits before production use.
